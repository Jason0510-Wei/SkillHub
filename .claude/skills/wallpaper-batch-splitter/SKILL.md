# 壁纸素材 8+1 分组

## 这是什么

下载来的壁纸通常按「帖子」归档，一个文件夹 18~25 张；但发小红书 / 公众号时是**按批次发**，每批固定 8 张壁纸，再加一张固定的封面/引导图（这个仓库里是「汤姆杰瑞仰望蓝天壁纸.png」）。

本 skill 把「按帖子分」改成「按批次分」：

```
处理/
├── 20261111-01/  18 张壁纸 + 1 张配图  ┐
├── 20261111-02/  18 张壁纸 + 1 张配图  │  拆分前：4 个文件夹，80 张壁纸
├── 20261111-03/  20 张壁纸 + 1 张配图  │
└── 20261111-04/  24 张壁纸 + 1 张配图  ┘

                    ↓ 每组 8 张 + 1 张配图

处理/
├── 20261111-01/  8 + 1   ┐
├── ...                    │  拆分后：10 个文件夹，仍是 80 张壁纸
└── 20261111-10/  8 + 1   ┘   （05~10 是自动新建、往下排号的）
```

## 默认规则

1. **现有编号文件夹各保留自己的前 N 张壁纸**（按文件名里的 `_NN` 数字升序，不是字符串序）。原有的配图不动。
2. **溢出的壁纸**按「文件夹编号 → 组内序号」汇总，每满 N 张就新建一个文件夹，编号接现有最大号往下排（`05、06…`，位宽沿用现有命名，如 `-01`）。
3. 每个新建文件夹都从母版复制一份配图，保证每组都是 `N 壁纸 + 1 配图`。
4. 最后一组不足 N 张时照建，并在结果里明确提示余数。

用 `--mode stream` 可改成「80 张完全按原顺序从头流式重排」：此时 `02` 里会是 `01` 帖子的第 9~16 张。默认 `keep-first` 更保守，尽量不打乱现有编号与素材来源的对应关系。

## 工作流

### Step 0 · 只读扫描 + 出方案（必做，不可跳过）

先扫描目标目录，把「有几个文件夹、每个几张壁纸、配图叫什么、总共多少张、会新建几个文件夹」报给用户，**确认后再动手**。目标目录为空、或用户说「我放了」之后内容变了，都要重新扫一遍。

```bash
python3 "<skill_dir>/scripts/split_folders.py" --root "<目标目录>" --dry-run
```

`--dry-run` 只打印方案，一个字节都不改。

### Step 1 · 备份 → Step 2 · 执行 → Step 3 · 校验

```bash
python3 "<skill_dir>/scripts/split_folders.py" --root "<目标目录>" --cover "<母版配图路径>"
```

脚本内部依次完成：

1. `shutil.copytree` 原样备份到 `<目标目录的父目录>/_<目录名>_原样备份_<时间戳>/`；
2. 计算分组方案，**两阶段移动**（先搬到临时暂存目录，再搬到目标），避免同名冲突与自覆盖；
3. 给每个新文件夹补一份配图；
4. 写映射 CSV（记录每个文件的原路径 → 新路径）；
5. 逐组打印 `壁纸数 / 配图数 / 合计`，并核对**壁纸总数守恒**、目标文件夹若已存在直接报错退出。

### Step 4 · 交付说明

告诉用户：一共几组、每组几张、哪几组是新建的、哪几组是跨来源混合的、备份在哪、映射 CSV 在哪；如果用户对分组方式不满意，用 `--rollback` 一键回到拆分前。

## 命令参考

| 目的 | 命令 |
|------|------|
| 只看方案（不改动） | `split_folders.py --root DIR --dry-run` |
| 标准执行（8 张 + 配图） | `split_folders.py --root DIR --cover "…/汤姆杰瑞仰望蓝天壁纸.png"` |
| 改每组张数 | 加 `--per-group 9` |
| 完全流式重排 | 加 `--mode stream` |
| 指定新文件夹起始号 | 加 `--start 5`（默认自动取现有最大号 +1） |
| 指定编号前缀/位宽 | 加 `--prefix 20261112- --width 2` |
| 不想自动探测配图 | 加 `--cover-name "封面.png"` |
| 跳过备份（不推荐） | 加 `--no-backup` |
| 回滚 | `split_folders.py --root DIR --rollback "<映射CSV>"` |

完整参数：

| 参数 | 默认 | 说明 |
|------|------|------|
| `--root` | 必填 | 待整理的目录，其**直接子文件夹**视为分组单元 |
| `--per-group` | `8` | 每组壁纸张数 |
| `--cover` | 自动探测 | 母版配图文件路径；省略时自动找「在多个文件夹里重复出现的同名图片」 |
| `--cover-name` | — | 显式指定配图文件名（含扩展名），优先级低于 `--cover` |
| `--mode` | `keep-first` | `keep-first` / `stream`，见上 |
| `--start` | 最大号 +1 | 新文件夹起始编号 |
| `--prefix` | 从现有名字推断 | 编号前缀，如 `20261111-` |
| `--width` | 从现有名字推断 | 编号位宽，如 `2` → `01` |
| `--backup-dir` | 自动 | 自定义备份目录 |
| `--no-backup` | 关 | 跳过备份 |
| `--map-csv` | 自动 | 自定义映射 CSV 路径 |
| `--dry-run` | 关 | 只打印方案 |
| `--rollback` | — | 传映射 CSV 路径，执行回滚 |

## 安全红线

- **绝不删除任何壁纸文件**。全程只有「移动」和「复制配图」；临时暂存目录只用 `rmdir()` 删空目录，非空就报错保留。
- **目标文件夹已存在 → 立即报错退出**，绝不合并、绝不覆盖同名文件。
- **默认强制备份**；备份失败就中止，不带备份跑拆分。
- **执行前后核对壁纸总数**，不守恒就报错并提示用备份/CSV 回滚。
- 移动采用两阶段：先把要搬的文件集中到暂存区，再分发；`stream` 模式会重排现有文件夹，也走同一套逻辑。
- 配图识别：优先用 `--cover` 的 basename；自动探测时取「在 ≥2 个文件夹里重复出现的同名图片」，探测不到就报错要求显式指定，**不会误把壁纸当配图**。
- 排序用文件名里的 `_(\d+)` 数字，避免 `_10` 排到 `_2` 前面。

## 异常处理

| 现象 | 处理 |
|------|------|
| 目标目录为空 | 别猜，问用户源在哪 / 让用户放好文件后重扫 |
| 探测不到配图 | 加 `--cover` 或 `--cover-name` 显式指定 |
| 编号格式推断不出来 | 加 `--prefix` + `--width` |
| 目标文件夹已存在 | 停手，让用户先清理或换 `--start` |
| 用户想换分组方式 | `--rollback <CSV>` 回滚后换 `--mode` / `--per-group` 重跑 |
| 最后一组不足 N 张 | 正常，结果里会标出余数组 |

## 给用户的简短说明

一句话说明「现在共几组、每组 8 张壁纸 + 1 张配图、没有丢图」，再给出备份目录和映射 CSV 路径即可，不用复述脚本实现细节。
