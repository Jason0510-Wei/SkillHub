# 一稿三发：三平台洗稿与排版

把一份信息密集的原始材料（通常是社区日报、行业研报、长文），改写成**三种不同视角、不同详略、不同语体**的稿件，分别适配今日头条、百家号、微信公众号的发布格式。

核心判断：**不是把同一篇文章复制三份，也不是同义词替换。** 三平台读者不是同一群人，停下来的理由也不一样。

---

## 何时使用

- 用户发来一份总结性 PDF / 日报 / 长文，要求"按三个平台输出"
- 要求"洗稿""分发""一稿多发""按受众差异改写"
- 已有稿件需要适配某个平台格式

## 输入

必需：
1. **源材料**：PDF 路径 / 链接 / 长文文本
2. **输出目录**（未指定则建在源文件同级 `YYYYMMDD_三平台稿件/`）

可选（有则显著提升质量）：
3. **账号人设**：如"🐒 每天搞懂一个科技梗"。公众号保留人设，头条/百家号弱化或不带
4. **已有栏目体系**：如"热点解码 / 概念深潜 / 科技冷知识"，用于给公众号稿件打栏目
5. **账号垂直领域**：决定头条/百家号的分类与标签

---

## 工作流

### 第 1 步：读源，建事实池

PDF 用你环境里的 PDF 解析能力转成 Markdown。不要直接把全文塞进上下文，先看篇幅与章节。

提取后**不要立刻动笔**，先做两件事：

1. **数信息点**：这份材料能拆出多少个独立事件？标出其中"有人物、有数字、有冲突"的。
2. **建事实池**：每条事实编号，并按信源分级——

| 等级 | 含义 | 能否直接写 |
|---|---|---|
| A 官方 | 公告、招股书、财报、监管文件 | 可写，注明来源 |
| B 媒体 | 有署名的正规媒体报道 | 可写，加"据报道" |
| C 社区 | 论坛讨论、用户实测、从业者转述 | 可写，加"有从业者提到" |
| D 传闻 | 推文、爆料、"据说" | **只能写"传闻"，不给具体数字** |
| E 证伪 | 已被辟谣或自证不实 | **整条删除，不写** |

详见 `references/rewrite-playbook.md` 第 2 节。

### 第 2 步：定主线（最关键的一步）

一份日报通常有 15-25 个信息点，**直接平铺 = 没有主线 = 没人读完**。

找主线的三个筛子，按顺序过：

1. **共同指向**：哪几条信息其实在说同一件事？（通常是钱、权力、风险、或普通人的处境变化）
2. **够不够近**：普通读者能不能在 10 秒内感到"这跟我有关"？
3. **有没有结论**：能不能用一句话说完，且这句话有点反直觉？

定不出主线时的兜底：**选"数字最大"或"变化最反常"的那条做主线，其余降级为佐证。**

**候选主线打分（DAIG，各 0-2 分，满分 8）**——有多个候选时用，**证据为 0 的直接排除**：

| 项 | 问什么 |
|---|---|
| **D 差异角度** | 别人会怎么写？我这个切入跟主流写法差在哪？ |
| **A 读者关联** | 目标平台读者能不能想到自己的钱／工作／家人？ |
| **I 信息增量** | 看完能带走什么他原本不知道的东西？ |
| **G 证据基础** | 有多少 A／B 级信源支撑？（社区转述只算半个） |

同分时优先 G → A → I。**内部打分不写进正文。**

头条还有个额外门槛：**能不能自然带上全民热词**（AI／华为／芯片／苹果／房价／黄金／存款利率）。同分时能带热词的胜出——它决定展现天花板，详见 `references/platform-specs.md` 第六节。

判断标准写在 `references/rewrite-playbook.md` 第 1 节。写之前先用一句话把主线说出来，如果这句话超过 40 字或含三个以上专有名词，说明还没想清楚。

### 第 3 步：合规清洗（必须在写作前做）

打开 `references/compliance.md` 逐条过。**这一步放在写作前，不是写作后**——先删再写，比写完再删省一半力气。

必删五类：教唆规避平台风控的操作、已证伪信息、无源具体数字、外链、荐股与医疗断言。

### 第 4 步：分平台改写

三份稿件的差异必须落在**视角、详略、语体**三层，不能只改措辞。

| | 公众号 | 头条 | 百家号 |
|---|---|---|---|
| 读者关系 | 订阅，认人设 | 推荐流，认内容 | 搜索+推荐，认信息 |
| 主线 | 全量，可多线并行 | **只留一条**，其余当佐证 | 一条主线 + 结构化信息 |
| 开头 | 观点或人设先行 | 场景/事件钩子，3 行内出冲突 | 结论先行 |
| 术语 | 保留原词 | 全部换成人话 | 保留但首次出现加解释 |
| 段落 | 3-5 行 | **1-3 行**，一段一个信息点 | 2-4 行，带小标题 |
| 字数 | 2500-3500 | 1200-1800 | 1500-2200 |
| 结尾 | 建议 + 互动 | 建议 + 报数式互动 | 总结 + 互动 |

字号、标题长度、禁项、发布时间等硬规格见 `references/platform-specs.md`。

**反搬运红线**：三份稿件的开头第一段、小标题文字、结尾互动句，必须完全不同。正文相同的连续段落不超过一段。平台判"全网搬运"看的就是这些。

### 第 5 步：写配图图位

**不需要真的生成图，但必须把"生成什么、放在哪"写得能直接拿去用。**

做法见 `references/visuals.md`。三条硬要求：

1. **描述放在正文的插入位置**，不要全堆到文末。用 `【图位N · 插在这一段下面，发完删掉本块】` 开头，用户照着插就行。
2. 每个图位给五样：**画面 / 色调 / 尺寸 / 英文提示词 / 注意事项**。
3. **中文文字不要交给 AI**——提示词统一写 `no text`，画面里明确留白，并提醒用户出图后自己加字。

数量：头条 3-6 张、百家号 3-5 张、公众号 3-5 张。封面选"信息量最大、缩小后仍能看懂"的那张。

**不要说"已配齐"或编造图片路径。** 未生成就写"配图为方案描述，尚未生成图片"。

### 第 6 步：按格式输出

在输出目录生成 5 个文件：

```
YYYYMMDD_三平台稿件/
├── 公众号.html        # 内联样式，可直接全选粘贴进微信编辑器
├── 公众号.md          # 纯文本源稿，改字用这个
├── 头条.md            # 元信息头 + 纯文本正文
├── 百家号.md          # 元信息头 + 纯文本正文
└── 发布说明.md        # 对照表、标题候选、时间、图位、合规清单、发布顺序
```

模板在 `assets/`：
- `wechat-template.html` — 公众号 HTML 骨架（内联样式，已适配微信编辑器）
- `meta-toutiao.md` — 头条元信息头
- `meta-baijiahao.md` — 百家号元信息头

**格式硬要求**：
- 头条、百家号正文**不得出现任何 Markdown 符号**（`**`、`##`、`- `、`>`），粘贴后会原样显示
- 公众号 HTML **不得用 `<style>` 标签**，必须全部内联；不用 flex/grid
- 元信息头与正文之间用分隔线隔开，并写明"复制时从哪一行开始"
- **纯净正文**：正文里不出现"来源：XX""参考资料"标签、引用卡片、外链、脚注编号、"下面是可直接复制的版本"这类助手提示语。来源与核查过程放 `发布说明.md`
- **图位说明块必须能被一键删除**，并在文首或元信息里注明"发布时删掉"

### 第 7 步：自检

```bash
python scripts/check_output.py <输出目录>
```

脚本会检查：元信息完整性、标题字数、正文字数、Markdown 残留、外链、标题党词与极限词、「第一是」误判写法、敏感操作词、未标注传闻、图位说明块是否残留、HTML 标签配对与 `<style>` 违规、三份稿件的反搬运比对。

其中**反搬运比对**是本技能最容易被忽略、也最致命的一项，四项检查见 `references/rewrite-playbook.md` 第八节：

- 三份标题相同 → FAIL
- 开头 60 字相同 → FAIL
- 最长连续重复段 ≥45 字 → WARN
- **小标题雷同 → FAIL；相似度 ≥0.75 → WARN**

> 注意：小标题只有 8-16 字，**永远撞不到 45 字的长段阈值，必须单独查**。只做长段检测一定会漏。

**脚本报 FAIL 必须改完再交付**，WARN 需要人工判断并在发布说明里写明。

### 第 8 步：交付说明

`发布说明.md` 必须包含这七块，缺一不可：

1. 文件清单（文件名 / 平台 / 形态 / 字数）
2. 三平台差异化对照表（说明改了什么、为什么）
3. 每平台 3 个标题候选
4. 发布时间建议 + 理由
5. 配图建议（几处图位、每处画什么、哪张当首图）
6. **合规处理清单**（删了什么、为什么删）+ **需人工确认项**
7. 发布顺序建议（含首发补贴冲突的取舍）

## 与其他技能的分工

- **单平台深度写稿**（只要头条，或只要公众号）→ 用你已装的单平台写稿技能，它们的写法颗粒度更细；本技能只负责"一份材料 → 三种形态"。
- **本技能只做"一份材料 → 三种形态"的分发改写**，不替代单平台精修。
- **自动发布** → 用浏览器自动化类技能或手动发。注意：若用了自动发布工具且它默认勾选"头条首发"，会与本技能的发布顺序建议冲突，用前先确认。

---

## 发布顺序：一个必须提醒用户的坑

头条「首发」补贴（约 1.5-3 倍分成）要求 72 小时内全网未发，与公众号首发**直接冲突**。

给用户的建议模板：

- 时效型内容（热点、突发）→ **公众号先发，头条 24 小时内跟进**（放弃补贴换时效），百家号次日早间
- 长效型内容（科普、方法论、评测）→ **头条先发吃补贴**，72 小时后再发公众号和百家号

不要默认让用户"全都同时发"——同时发等于三边都拿不到首发权益，还容易被判搬运。

---

## 边界

- 不代发布，只产出可复制的稿件与发布说明
- 不编造源材料里没有的事实、数字、引语
- 源材料信息不足时，宁可稿件短，不注水凑字数
- 涉及上市公司、医疗、法律的内容，必须加"以官方公告为准""具体请遵医嘱"类兜底
- 用户明确要求指名道姓批评某公司时，先提示商业诋毁风险，再按用户决定执行
