# 洗稿方法论

> 洗稿不是换词，是**换视角重建**。同一批事实，三种读者，三种讲法。

---

## 一、定主线：三个筛子

一份 20 个信息点的日报，直接平铺必死。主线是唯一能让读者读完的东西。

### 筛子 1：共同指向

把信息点两两配对，问"这两条是不是在说同一件事？"

实战例子（linux.do AI 日报 → 三平台稿）：

| 信息点 | 表面看是 | 实际指向 |
|---|---|---|
| 李佳琦直播卖 Token | 营销事件 | 向 C 端要现金流 |
| 马斯克承认 Grok Bot 成本撑不住 | 产品调价 | 补贴不可持续 |
| OpenAI 只给高价席位加量 | 额度规则 | 差别定价 |
| Anthropic 承诺支出 8954 亿、禁转售 | 财报 + 条款 | 堵套利、按成本定价 |

→ 共同指向：**AI 从"抢用户"切换到"算清楚成本"**。这就是主线。

### 筛子 2：够不够近

读者的 10 秒测试：这条信息，能不能让他想到自己的钱包 / 工作 / 家人 / 明天要做的事？

- "GPT-6.2 API 降价 60%" → 只有开发者有感，**不够近**
- "你每月在 AI 上花的钱要变多了" → 所有人都能代入，**够近**

**技巧**：把行业事件翻译成"对普通人的影响"，就自动变近了。

### 筛子 3：有没有结论

好主线能用一句话说完，且这句话有点反直觉。

- ❌ "AI 行业发生了很多变化"（不是结论）
- ✅ "AI 的免费午餐正在收摊"（是结论，且和大众预期相反）

如果一句话超过 40 字，或含 3 个以上专有名词，说明还没想清楚，回去重新配对。

### 定不出主线的兜底

选**数字最大**的那条，或**变化最反常**的那条做主线，其余全部降级为佐证。
数据量大的材料里，通常有一条"体量最夸张"的事实（如"半小时卖 2 万亿"），它自带钩子。

## 二、事实分层：五级信源

写作前给每条事实打标，决定它能以什么口径出现。

| 等级 | 判断依据 | 写法 |
|---|---|---|
| **A 官方** | 公告、招股书、财报、监管文件、法院判决 | 直接写，注明"根据招股书/公告" |
| **B 媒体** | 有署名的正规媒体报道 | "据 XX 报道"（能查到媒体名就写名字） |
| **C 社区** | 论坛讨论、用户实测、从业者转述 | "有从业者提到""有用户实测" |
| **D 传闻** | 推文、爆料、"据说" | 只能写"传闻称"，**不给具体数字** |
| **E 证伪** | 已被辟谣、原文已标不实 | **整条删除** |

**常见错误**：把 C 级社区共识写成 A 级事实。典型句式"业内普遍认为……"——如果只是几个论坛帖子，就该写"在技术社区里，比较多的一种看法是……"。

## 三、视角重构：三个问题

动笔前对每个平台回答一遍：

1. **他为什么停下来？**（钩子）
2. **这跟他有什么关系？**（相关性）
3. **他看完会做什么？**（转发 / 收藏 / 评论 / 划走）

| | 公众号 | 头条 | 百家号 |
|---|---|---|---|
| 为什么停 | 标题有观点 + 信任作者 | 开头三行有冲突/数字 | 标题命中他在搜的词 |
| 跟他什么关系 | 认知升级 | 钱包、生活、身份 | 信息补全 |
| 会做什么 | 收藏、转发朋友圈 | 评论、转发家庭群 | 收藏、搜索更多 |

## 四、详略分配：谁拿什么

同一批事实，三个平台分到的"料"完全不同。

**公众号 = 全量**
所有 A/B 级事实都进，C 级挑有趣的进。可以多线并行（主线 + 技术线 + 边角料），因为读者已经订阅了，愿意读完。

**头条 = 一条主线 + 两个故事**
只留支撑主线的 3-4 条事实，加上 1-2 个"有人物、有画面"的边角故事（如"巴西律师白底白字给 AI 下指令"）。技术细节全部删掉或降级成一句人话。

**百家号 = 一条主线 + 结构化信息**
主线 + 五到七个小标题，每个小标题下一个信息点。信息密度最高，因为要接搜索长尾。但每条都要能独立读懂（读者可能从中间某段搜进来）。

## 五、语体迁移表

头条/百家号读者不认术语。给一张对照：

| 原文术语 | 头条写法 |
|---|---|
| Opus 5.5 指挥 GPT | 用强模型做决策，用快模型干活 |
| Token 单价 | 算力的价格 |
| 中视频伙伴计划 | （不写） |
| 上下文 200K | 一次能记住多长的内容 |
| MoE / 激活参数 | （不写，除非主线需要） |
| 反代 / 中转站 | （**删**，见合规清单） |
| 灰度 | 小范围试用 |
| 路由 | 自动派活给不同的模型 |
| 推理成本 | 跑一次要花多少钱 |

**原则**：一个术语如果不能在括号里用 8 个字解释清楚，就别用。

## 六、开头三行模板

### 头条（场景 / 事件 / 冲突）

**A. 场景钩子**
> 11月2日晚上七点半，李佳琦直播间上架了一件很奇怪的商品。
> 不是口红，不是面霜，是Token。

**B. 反差钩子**
> 同一天，有人半小时卖了2万亿Token，有人说这生意撑不住了。

**C. 数字钩子**
> 半小时，10万份，2万亿。这是昨晚一场直播的成绩。

### 百家号（结论 / 判断）

> 把这一周分散的几条消息放在一起看，会发现它们指向同一个结论：……

### 公众号（人设 / 观点）

> 🐒 猴子冲浪回来了。
> 这周最该懂的事，不是又出了个多强的模型，是一件更朴素的事：……

## 七、结尾互动：要"报数"，不要"你怎么看"

低效互动：`你怎么看？欢迎留言`（读者不知道说什么）

高效互动：给一个**极低成本的回答动作**

- `你每个月在 AI 上花多少钱？评论区报个数`（一个数字就能答）
- `你是白嫖党还是已经订阅了两三个？`（二选一）
- `你那儿有没有这种冷门地方？`（分享一个具体物）

**原理**：评论区互动率是推荐权重项。让读者"打三个字就能答"，比让他"写一段感想"高十倍。

## 八、反搬运自检

### 平台怎么判"全网搬运"

**平台不看全文重复率，看两样更狠的东西：**

1. **最长连续重复段**——哪怕全文只有 5% 重复，只要有一处连续 40-50 字一模一样，就可能命中
2. **小标题是否雷同**——小标题是"结构指纹"。三份稿子的小标题如果一致，即便正文全改了，机器仍能判定同一模板生产

所以"换了同义词"没用，"改了段落顺序"也没用——**小标题和连续段才是命门**。

### 脚本怎么查

`scripts/check_output.py` 的 `check_duplication()` 三向比对，四项检查：

| 检查 | 阈值 | 判定 |
|---|---|---|
| 三份标题是否相同 | 完全相同 | **FAIL** |
| 开头 60 字是否相同 | 完全相同 | **FAIL** |
| 最长连续重复段 | ≥ 45 字 | WARN |
| 小标题是否雷同 | 相同 → **FAIL**；相似度 ≥ 0.75 → WARN | — |

小标题必须单独查：**小标题通常只有 8-16 字，永远撞不到 45 字的长段阈值**，光靠长段检测会漏。

抽出规则：`一、xxx` / `【一】xxx` / `（一）xxx` 的行，公众号 HTML 取 19px 加粗 span。

### 实测数据（本技能的第一次真实运行）

首轮交付后脚本报出：

```
[WARN] 头条.md 与 公众号.md 有 99 字连续重复   → Grok 段
[WARN] 头条.md 与 公众号.md 有 96 字连续重复   → 四件事总结
[WARN] 头条.md 与 公众号.md 有 67 字连续重复   → Token 量级段
[WARN] 头条.md 与 公众号.md 有 66 字连续重复   → 巴西律师段（含引语）
再加上 2 个小标题一字不差
```

逐段重写后归零。**教训：同一批事实分给三个平台时，最容易雷同的四类位置是——**

1. **核心判断句**（"四条指向同一个方向：……"）→ 头条改成分述，不要用并列短句
2. **引语 + 紧随其后的解释**（"据XX称……翻译一下……"）→ 引语可以短，解释必须换说法
3. **量级对比段**（"X 是什么概念？参照物是……"）→ 换参照物，或换叙述顺序
4. **案例描述段**（"某国两名律师……法院认定……罚款 X"）→ 只保留最短的事实骨架，其余重讲

### 修法：不是换词，是换骨架

| 无效改法 | 有效改法 |
|---|---|
| 同义词替换（"说"→"表示"） | 换叙述顺序（先结论后事件 / 先事件后结论） |
| 调换段落位置 | 换文体（并列短句 → 连续叙述；叙述 → 分点） |
| 加一句自己的话 | 换参照物、换类比、换切入人物 |
| 只改小标题的字 | 换小标题的**信息角度**（例：「一份不太好看的账本」→「最狠的一份账本」→ 仍相似；改成「营收332亿，承诺支出8954亿」才够远） |

### 交付前手工过一遍

- [ ] 三个标题互不相同
- [ ] 三份的开头第一段互不相同
- [ ] **小标题逐条对照，没有一条雷同或高度相似**
- [ ] 结尾互动句不同
- [ ] 脚本跑过，反搬运无 FAIL
